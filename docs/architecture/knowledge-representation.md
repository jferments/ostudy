# Knowledge representation and evidence ownership

This is the maintained contract for `knowledge/` and its document, Tutor and artifact consumers. [AI and document processing](ai-and-document-processing.md) describes the surrounding pipeline; [the Tutor acceptance contract](../development/semantic-ai-tutor-implementation.md) defines qualification. GitHub records the tested source revision separately.

## Separate evidence, interpretation and presentation

Canonical documents, user-authored cards, imported content and effective guide sections remain the material the learner owns. An AI interpretation never replaces those records. A conversation can be retrieved only under its explicit privacy rules and is never promoted to independent document evidence.

`SourceRecord` is a bounded, revision-aware projection over that material. Its identity identifies the material/segment; its content hash binds the evidence revision. New document projections use identity version 2, which excludes display titles from the evidence hash. Legacy serialized records default to version 1 and remain readable. Changes to source content or assets invalidate dependent interpretations, while changing a title alone does not make v2 canonical text different.

`EvidenceReference` belongs to native code. A text selector contains half-open UTF-8 byte offsets into the exact hashed source text. Its excerpt is obtained by slicing that source, not by asking a model to quote it. The native span builder preserves text bytes and chooses bounded locations; it does not claim to solve linguistic sentence segmentation. Several adjacent or disjoint spans can support one interpretation. Image evidence identifies an admitted managed asset, and only images actually attached to the analysis request are available for selection.

`KnowledgeUnit` is a fallible interpretation: a definition, relationship, comparison, process or fact-shaped statement, with qualifications, topic and advisory importance. Its grounding contains one to eight native references. References may span multiple sources of the same document. A unit cannot mix a user assertion, generated derivative or unrelated document into an apparent single original-source authority. The legacy primary-source/excerpt fields are compatibility projections; the complete evidence list governs v2 dependencies.

Artifact links describe what a card assesses or a guide explains. These are explicit native-validated relationships, not citations inferred from text similarity. A vector index supports retrieval but owns neither source identity nor truth. Document outlines and global core-ID selections are derived learning views, not new sources.

## Loss-aware canonical structure and qualified units

Migration 18 adds immutable `document_evidence_payloads`, document-owned `document_evidence_occurrences`, and occurrence links. Payload content identity is separate from occurrence ownership, reading order and location. Identical payloads can serve distinct documents without merging their ownership. Reordering unchanged unambiguous occurrences preserves their identity; ambiguous matching is not promoted into proof of equivalence. Existing source originals and asset lifetimes remain with their current owners.

Canonical table grids preserve supplied cells, spans, header labels, bounds and explicit links. Text is a deterministic projection, not a replacement for grid authority. Code retains intrinsic indentation and literal operators separately from source-layer labels. Missing extractor structure is not invented. The local migration backfill reuses retained canonical records; it cannot reconstruct unavailable historical cell semantics. Screenshot overlap detection and reversible filter producers remain LK-04, and interpretation output cannot declare an evidence region filtered or verified equivalent to another.

`typed_payload.rs` supplies narrowly bounded comparison, process, quantity and classification detail. Values are native UTF-8 spans into the one authoritative statement; prompts derive their text from those spans. Numeric signs, precision, inequalities, units and conditions therefore are not copied into a second mutable authority. Process dependencies are validated as a graph rather than assumed to be a total order. Classification can retain overlapping membership. This structural validation still does not prove the statement follows from its source. Existing valid units without detail retain their bytes and identities; absent detail remains unavailable.

## Provider contract and factual limits

A request presents an evidence catalog with short local aliases such as `E0`. The provider returns statements and selected aliases. It does not choose authoritative hashes, byte offsets, origins or quotation text. Native code resolves IDs, enforces source membership, checks revisions, rejects duplicates and retains all dependencies.

This proves where the selected evidence is, not whether the model's statement follows from it. Selecting a real but irrelevant passage remains a semantic quality error. Structured output cannot establish truth, exhaustive extraction, useful question direction or faithful preservation of every qualification. Prompts require preservation of conditions and contradictions; tests explicitly distinguish location validation from entailment. No fuzzy matcher, hidden confidence score or automatic factual-verification label overrides that distinction.

Manual material keeps user-authored origin. Repeated AI-generated cards or guides do not count as independent corroboration. Retrieval may expose the original evidence alongside a derivative; it must not silently treat the derivative as a stronger authority.

## Generated-output protocol boundary

The application schema is sent both in model instructions and in the provider's structured-output mechanism. Provider schema lowering visits schema nodes, not arbitrary JSON objects: property names and literal enum/default objects are data. Portable wire schemas can omit unsupported bounds; the full schema remains visible in instructions and native validators enforce those bounds. A response is a proposed JSON instance, never an authority-bearing IPC or storage record.

Knowledge extraction requests `units` and `noLearningSourceIds`, with optional per-unit qualified `details` and explicit `regionDispositions`. Native admission remains responsible for their types, bounds and evidence authority. It admits independently valid proposals from the named `units` array; a bare proposal array is the one documented alternate envelope. Missing, null or unusable ancillary dispositions mean no usable dispositions, not loss of otherwise valid units and not permission to mark an uncovered source complete. Unknown envelope properties are diagnosed and ignored, not promoted into evidence. Arbitrary `data`, `sources` or `results` wrappers and invented field aliases are not guessed. Missing or incorrectly typed primary content still requires repair. Per-unit evidence, source authority, cardinality and revision rules remain unchanged.

Targeted repairs similarly isolate their explicitly named collections. An unusable ancillary collection cannot erase valid independent corrections. A schema-shaped diagnostic is advisory at transport: whole-response validation there would recreate the all-or-nothing failure boundary. Domain decoders decide admissibility. Native IPC, durable receipts and source contracts continue using their strict typed validation.

Shared transport rejects refusal/filter responses and output-length termination even when the returned fragment happens to parse as JSON. It reserves context for the schema-bearing prompt and completion before a request. Invalid or excess admitted images are errors rather than silently omitted evidence. No provider fallback disables evidence validation.

## One reusable semantic analysis

Document adapters preserve canonical chunks and their locators. Bounded analysis neighborhoods can join neighboring source records from the same document rather than interpreting each physical page independently. Hydration batches carry unfinished neighborhoods forward so a database batch boundary does not become a conceptual boundary. Request budgets still impose finite context: the system does not claim unlimited cross-document or long-distance synthesis.

Saved interpretations belong to the canonical source revision, not to the consuming LLM. The producer contract remains recorded for provenance and repair, but selecting another Tutor or guide model does not invalidate compatible knowledge. Original ordered window receipts are reused across consumer-model changes. A subset can read saved units without replacing a wider window's analysis. Only source edits, explicit analysis repair, or incompatible evidence contracts require interpretation work.

Independent cloud analysis windows run with bounded concurrency (up to four); local inference retains its serial topology. Each started sibling checkpoints before a batch failure is returned. Window sizes, evidence validation and quality requirements are not reduced to obtain a speedup. Progress counts completed source projections rather than hydrated database batches.

Shared knowledge is prepared before constructing the outline or authoring cards and guides. The old raw-source outline traversal is not run in parallel with a second knowledge traversal. Native grouping creates a bounded topic/source-range view. An optional balanced knowledge-only reduction supplies broader context and a small core-unit set; if every nonempty input window cannot fit, it falls back locally instead of silently dropping the tail. Importance is advisory. No automatic semantic merge destroys conflicting claims, and exclusion from a sampled global set does not mean a unit is unimportant.

Artifact prompts receive selected knowledge, a deduplicated catalog of its exact evidence, compact global context and applicable visual inputs. They do not repeat the complete raw source window alongside copies of its excerpts. Cards select their actual unit targets; guides retain support for their sections. When the provider returns more cards than requested, native code first validates every returned card and its targets, then selects whole cards within the budget, favoring distinct and higher-priority knowledge. It never cuts a question or answer to fit. A separate hard response ceiling remains, and invalid surplus content still fails validation. Existing transactional artifact publication, cancellation and scheduling boundaries remain in force.

Study-guide requests use short `K0`-style aliases mapped back to the exact supplied native units. Alias resolution cannot introduce new targets or hide duplicates. Missing/null optional outline categories can be represented as empty arrays; mandatory content, key points and evidence selections cannot be invented. Text-only request schemas and instructions require an empty visual category. If a provider nevertheless supplies optional visual explanations without attached images, the decoder omits that category, records a content-safe diagnostic, and validates the remaining text and evidence normally; unsupported visual claims are never published. The compact learning plan remains valid JSON: the active topic is retained first, whole background topics are omitted with an omission count, and no factual sentence or serialized object is cut mid-value.

Guide contract/truncation failures receive one bounded repair with safe field feedback and, when bounded, the invalid draft itself as untrusted data. The draft is not logged or accepted as evidence. The repair has additional output headroom and hard content limits. Concise outline targets are advisory: a section is not rejected merely for exceeding a stylistic target. Native validation checks hard bounds before the authored-content normalizer so an overlong claim cannot be silently truncated. Evidence selection and mandatory teaching content remain strict. Every successful member of a completed parallel topic batch is checkpointed before a sibling failure is propagated. Checkpoint format v3 invalidates older derived section candidates without deleting published guides, annotations or shared semantic analysis.

## Shared preparation and learning context

`knowledge/extraction/shared.rs` binds active work to the exact source window, interpretation contract, captured provider/network authorization and repair permission. `shared_preparation.rs` coordinates compatible subscribers inside the native application. It does not create another service or publisher. Canceling one subscription leaves work needed by another subscription running; the final subscriber cancels further work. Dropping the driving future reports interruption to waiters rather than silently retrying a provider. Successful analysis checkpoints remain in SQLite. Process-local coordination does not claim durable in-flight network execution across restart.

`LearningContextRequest` is the common read-only admission boundary used by card/guide catalog construction and Tutor material assembly. Its native caller supplies authorized scope, focus/ranked candidates, target units, coverage/retrieval policy and explicit budgets. IDs alone grant no permission: allowed sources are checked before hydration and records are reloaded. Whole claims require every evidence dependency to survive scope filtering and budget admission. Coverage mode refuses an incomplete source/unit window instead of relabeling top-ranked results as complete coverage; retrieval mode records omissions. Authoring can include a dependent page only within its explicitly selected document.

The result contains admitted sources/units, exact evidence, bounded canonical structures, preparation limitations and a revision stamp. It performs no provider call. Unprepared sources, unresolved/unreadable regions, rejected proposals and older coverage receipts remain distinguishable. The shared prompt keeps source excerpts separate from interpretations. Consumer-model changes do not invalidate compatible saved knowledge; embedding changes rebuilds only the replaceable index.

Tutor keeps conversation, question and hint policy in its own modules. Typed hidden-answer hints retain their separate public-question path. Ordinary material context loads images only from admitted sources, removes a claim when required evidence is evicted, and validates its stamp in the turn publication transaction. Scope exclusion cannot be bypassed by a focused image or backing link. Later lesson composition will consume this same boundary when LK-10 introduces lessons; no lesson player or folder synthesis is present in LK-03.

## Failure boundaries and resumability

A malformed transport response is a request failure. A malformed unit or nonexistent evidence ID is a proposal failure. A changed canonical source or competing interpretation is a stale-work failure. These do not have the same recovery semantics.

A bounded analysis report stores admitted units, rejected proposal slots and revision-bound evidence-region dispositions. New receipts account for interpreted, retained-metadata, no-learning, unreadable and unresolved regions. A source with one accepted span can still have unresolved regions; an image not attached remains unresolved rather than implicitly understood. Conflicting or malformed declarations cannot certify missing regions. Admitted units are published before a targeted repair request. A cancellation, provider outage or bad repair cannot erase those siblings. The provider repairs rejected slots and uncovered regions only; it is not asked to regenerate all successful output. Invalid slots remain unresolved. Duplicate/conflicting slots do not choose a winner by order, but independent successful repairs are retained.

An explicit no-learning disposition distinguishes publishing scaffolding or other non-learning content from a missing response. A null repair is still unresolved. A partial receipt is not a completed extraction, even when it provides useful units. The durable report and debug logs retain unresolved counts; Tutor uses accepted knowledge without launching more interpretation. Nonfatal analysis/coverage diagnostics are not ordinary UI banners, success-toast warnings or text appended to Tutor replies. Native code records context diagnostics separately, while genuine request failures remain visible and actionable. Usable output is not represented as exhaustive merely because its internal diagnostics are not shown in the main UI. For current receipts, “complete” means every planned evidence region has a protocol disposition and rejected proposals are resolved; older compatible source-level receipts remain explicitly identified as older coverage. This does not certify exhaustive recall of every concept in a textbook.

The former 16-unit-per-primary-source quota is removed. The 128-unit ceilings are bounded admission/storage guards, not requested quotas or measures of pedagogical quality. Retained `unit_capacity` drafts are revalidated locally against their original ordered, revision-matched evidence catalog before another provider request. A capacity rejection is not a finding that the statement is false. Genuine content/evidence failures remain unresolved; no blank disposition is manufactured to clear a warning.

Completed checkpoint reuse is read-only. It does not rewrite units, reset artifact links or invalidate a cached overview. A checkpoint binds the exact source revisions plus the current interpretation and receipt revisions before provider work. Its save checks that snapshot in the same short SQLite transaction as publication. A concurrent writer cannot silently overwrite newer admitted work. If source packing or extraction contracts change, obsolete overlapping receipts are retired and untouched siblings are marked for reanalysis rather than remaining falsely complete.

Retries remain explicit user actions. Startup reconciles interrupted tasks but sends no provider request. A retry of a partial matching window targets its unresolved work; a retry of a complete matching window makes no provider request. Subset preparation cannot silently expand consent to a larger source neighborhood.

## Revision safety beyond nonempty units

A unit depends on every selected evidence source, not merely its primary compatibility source. Native dependency rows and invalidation triggers remove stale interpretations and queue index eviction when any source changes. Artifact publication verifies support inside its existing transaction; edited material never gains invented citations.

Whole-document views need a stronger boundary than checking their nonempty catalogs. A source with no units, a changed no-learning disposition or an added canonical chunk can change the meaning of an overview. `DocumentSnapshot::prepared` verifies the original canonical plan and every expected prepared source projection, including empty results. An ordered, length-framed digest binds canonical content, assets, source revisions, units, receipts, immutable evidence payloads, source occurrences and structure links. A changed table role, location or footnote relation invalidates publication even when flattened text is unchanged. Display names and progress timestamps are excluded.

The snapshot is rechecked around provider reduction and inside the final publication transaction. The derived outline, metadata and ready-state update publish atomically. A changed, added, removed or reinterpreted source prevents that stale result from committing. Native fallback summaries use whole labels, not clipped factual sentences that could lose negations or conditions.

Tutor context applies scope/privacy filters before retrieval and checks current references again. A multi-source unit is usable only when all its supporting sources survive scope filtering and context-budget eviction. This is an all-dependencies rule, not permission to retrieve private material merely because it is linked.

## Search indexing and consumer scope

`knowledge/indexing.rs` only embeds saved source projections and admitted units; it has no interpretation-model call. Document processing attempts indexing automatically with the configured embedding profile. An unavailable embedding profile leaves the authoritative knowledge saved and indexing deferred. Sending a material-scoped chat or using explicit index maintenance catches up missing vectors. Cached vectors are reused; changing embedding space rebuilds this derived index, not source interpretations. Ordinary saves, startup, navigation and opening the Sources dialog make no provider requests. Raw authored/imported card text is searchable without an extra LLM interpretation pass.

Document collections are intentionally one level. Collection membership is only an authorization/organization reference to retained document knowledge; the same prepared document can participate in several collections without cloning or reinterpreting its semantic representation. CollectionSynthesis is a derived higher-level map over those source-owned units/evidence: topic grouping and cross-document relationships may change with membership/ranges, but source facts, evidence identities, embeddings, and per-document interpretation remain owned by the documents. Collection synthesis can be rebuilt from that retained knowledge without a document-processing/provider pass, and later lesson composition must consume the same LearningContext boundary rather than create a replacement interpretation layer.

Tutor uses one shared native scope contract. Legacy general, library and single-material scope JSON remains readable. A checklist yields at most 16 distinct deck/document/guide/collection members, sorted canonically; zero choices means general discussion and one member uses the legacy single-scope identity. Nested selections, wildcard members, duplicates and invalid IDs are rejected. Changing a saved conversation's Sources starts a new conversation, never mutates the old transcript's permissions. For a project chat that new conversation keeps project membership while recording the explicit source override. Selected documents include their linked artifacts and selected decks include their backing documents; selecting a deck does not authorize cards from another deck merely sharing that document.

Tutor projects are an organization/default layer, not a retrieval scope. A project stores title, description/instructions, current default scope, archive state and an organization revision. New project chats use the current default unless the learner explicitly supplies a source override. Moving an existing chat changes only project membership unless destination defaults are explicitly requested. Each admitted turn freezes its effective source scope and project instructions before provider work; later project/default/move changes cannot rewrite that historical authority.

SQL applies the selected union before vector ranking. Final hit admission rechecks the same permissions and revisions after ranking, including every evidence dependency. Conversation retrieval is opt-in for the exact entire material selection, not the union of each member's private conversations and never the set of conversations sharing a Tutor project. Historical conversation projections are admitted against the turn's frozen scope, not a later moved conversation scope. Revoking sharing or forgetting earlier turns removes their eligibility. General chats, collection scopes, and hidden-answer hints do not search conversation projections. These checks also apply to retrieval previews, not just the chat prompt.

## Persistence, migration and privacy

Migration 14 adds evidence dependencies, analysis receipts and document views. It does not rewrite existing migrations or delete canonical documents, ordinary notes, guide edits, conversations, review events or schedules. Legacy provenance remains readable; new extraction no longer asks for provider-written quotations. The multi-source scope extension adds no migration, but older binaries cannot read newly saved selection-scope conversations. An older binary cannot reverse an applied migration; preserve a compatible library backup before testing migration-bearing builds.

Migration 18 and the shared entry boundary preserve the existing migration chain. Startup/backup admission validates new typed detail and region receipts read-only before conversion writes; unsupported versions and forged plans fail unchanged. No provider analysis or personal-library adoption is implied by migration. Migration 25 adds Tutor projects, retry-safe organization receipts, conversation organization/archive state, and a nullable `captured_scope_json` on turns; migration backfill freezes each preexisting turn to its conversation's scope before later project moves can change the conversation. Migration 26 is a narrow collection-organization migration: it flattens any schema-25 nested document-folder rows to top level, bumps affected organization/folder revisions, and prevents future nesting while leaving document membership, ranges, source knowledge, and collection synthesis ownership intact. Whole-library backups preserve Tutor organization together with authoritative source/relationship, structured evidence and analysis state under the normal maintenance admission rules. Semantic vector files remain derived and rebuildable. Device-transfer sanitization removes Tutor projects, organization receipts, chats, and private/derived semantic projections; it does not treat full backup and device sync as interchangeable contracts. Source deletion cascades its owned dependencies while unrelated learner content retains the existing preservation rules.

Rejected drafts are bounded private application data, not diagnostic output. Logs record source IDs/locations, counts, native rejection categories, fingerprints, phases and provider usage; they exclude document text, generated drafts, prompts, credentials and model reasoning. A content hash is a diagnostic identity, not encryption or a promise of anonymity.

`structured_output_shape_mismatch` records application-schema paths, expected/actual types, missing required fields and counts of unexpected fields. It never copies unknown provider field names, values or raw Serde error strings. Inspection has depth/work/result bounds. `knowledge_envelope_repair_started` and `study_guide_repair_started` identify the bounded repair; `study_guide_topic_failed` records the topic index and source range without the topic text. A shape warning may describe safely recovered ancillary output, so inspect the subsequent admission/completion event rather than assuming every warning is fatal.

## Structured provider output

The gateway assembles literal streaming deltas separately for each tool-call
index. Complete-message snapshots must extend the corresponding accumulated
content; they must not be appended as a second copy. It bounds invocation count,
identities, argument bytes and total wire bytes. Tool arguments from different
invocations are never concatenated into one JSON string, even when names match.
The provider adapter validates the expected tool name and parses every result;
multiple results stay a collection rather than silently selecting the first.
Only knowledge analysis has additive collection semantics: its domain decoder
joins explicitly named initial/repair arrays under the existing aggregate bounds
before native evidence admission. Mixed envelope/proposal collections are rejected,
and duplicate repair slots remain visible to conflict detection. Scalar Tutor,
overview and guide replies are not combined into invented composite answers.

Tool arguments and content JSON share bounded formatting normalization: a complete
JSON fence/BOM, one JSON-encoded object layer, trailing commas after actual values,
literal control characters inside strings, and invalid non-Unicode escapes.
Normalization does not invent missing values, quotes, separators or closing
brackets, repair damaged Unicode, complete truncated output or relax evidence
validation. A malformed required result still receives the caller's bounded retry,
not an unbounded recovery loop. `structured_json_parse_failed` records category,
line, column, byte count and fingerprint without parser text or response values.
`structured_json_normalized` and `structured_tool_results_separated` record safe
recovery; `provider_stream_completed.toolCallCount` exposes invocation count.

## Budgets and verification

Planning includes the semantic-analysis traversal, allowed repair work, optional global reduction and artifact generation. Source-token estimates, provider-reported usage and billing are distinct quantities. No performance or cost-reduction percentage is claimed without measurement on representative documents. Source, request, proposal, receipt and snapshot bounds prevent unbounded work, but a complete large document may still require many provider requests.

Native regression tests cover exact Unicode/PDF spans, unknown and duplicate aliases, multi-page references, sibling survival, partial/null repair, malformed repair entries, source edits during provider work, empty-result invalidation, canonical-plan completeness, competing checkpoint writers and obsolete receipt retirement. Provider-lowering-to-decoder-to-SQLite fixtures cover the shared response contract for OpenRouter, DeepSeek and llama.cpp; guide tests cover optional categories, short aliases, context serialization, output truncation and preservation of successful parallel siblings. Existing Tutor, backup, privacy, migration and platform suites remain required. Deterministic fixtures do not prove live OpenRouter model quality, provider retention behavior or physical Android lifecycle behavior.

LK-03 regressions add request-counted reuse, subscriber cancellation/interruption and authorization isolation, region-level coverage/repair, typed payload round trips, context scope/budget eviction, structure-only snapshot invalidation, and current-format entry refusal. The complete-library preservation fixture now decodes structured evidence and typed partial knowledge after reopen and both rollback/committed restore. `scripts/test-native-contracts.sh` ensures selected current-format filters match real tests; compilation alone is not execution evidence. Exact-SHA static/fast, full Linux, Android compile/package, emulator, live-provider and human source-quality review remain separate claims.

Sources are optional for Tutor explanations and user-requested questions. General
scope does not call embeddings. Empty reference arrays are valid in every scope;
nonempty reference arrays must still resolve to supplied, current, permitted
material. Missing/temporarily unavailable retrieval may fall back to model
knowledge, never fabricated citations. Cancellation, stale evidence, revoked
permissions and storage errors remain hard boundaries. Prompt instructions
separate supplementary model knowledge from source claims and preserve explicit
source-only requests. Structured questions are validated independently of their
redundant public prose: native publication uses the validated question, keeping
private expected answers out of that prose. A source-free saved question can be
answered using its fixed rubric without inventing a provenance dependency.

The main Tutor UI contains chat, conversation history and an optional Sources checklist. Ordinary Send supports explanations, user-requested questions and conversational feedback; there is no separate Quiz me button or practice-exam feature. When a reply supplies a structured single question, native code preserves the private pre-answer rubric, publishes the corresponding pending-question state, and retains the original request hash for duplicate-safe replay. Hint and fixed-answer evaluation invariants are unchanged.

Tutor responses, including saved history, render Markdown through the exact-pinned `marked` 18.0.12 lexer (MIT). This dependency supplies established Markdown tokenization instead of a home-grown syntax parser, works in the existing bundled WebViews, and adds no native service or network requirement. Application-owned React rendering handles headings, emphasis, lists, tables, blockquotes and code. It never injects provider HTML, automatically loads images, or copies arbitrary token attributes into the DOM. Allowed external links open only on explicit activation through the existing platform adapter. Inline and fenced code retain literal content; parse/size/depth fallbacks retain readable text. Hints remain plain text to preserve their narrower disclosure contract. A rendering test is not a guarantee of visual fidelity on every device.

The main Tutor UI keeps its routine controls compact. Advanced privacy and index maintenance live in Chat settings. Confirmed terminal failures expose Try again only for the latest failed response; uncertain acknowledgements use Check response with the original operation identity. Earlier failed quiz answers cannot become answers to a later pending question. Historical hints require a fresh Practice context.

Documents task coordination lives above route transitions. Navigating elsewhere does not request cancellation. Study-guide generation uses a single generating/stop control with a red stop-sign icon; cooperative cancellation and failures remain observable on return. A successful write remains successful even if the following list refresh fails. Closing the process is different from leaving a route and still relies on durable restart/checkpoint reconciliation.

For live diagnosis, build the verified PR head using `./scripts/ostudy-dev build`, then run `./scripts/ostudy-dev run --log-filter='warn,ostudy.app=info,ostudy.ai=trace,ostudy.documents=trace'`. Preserve terminal output and the launcher/application diagnostic files immediately after failure. Keep the same provider, model and reasoning setting for the first regression test and retry retained material rather than deleting the library. See [the command runbook](../development/command-runbook.md) for maintained build and platform commands.
