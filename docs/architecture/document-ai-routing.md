# Document AI routing and concurrency

Document hierarchy and provider request boundaries are deliberately separate concerns in ostudy.

Semantic extraction preserves headings, page/source provenance, element types, and section relationships. Provider requests are then packed by bounded source-token and source-unit capacity rather than splitting every time a heading changes. A highly structured textbook must therefore not degenerate into one outline request per heading or page.

For large documents, outline and flashcard windows are independent units of provider work. Cloud-backed windows may execute with bounded concurrency while checkpoint/database writes remain serialized in source-window order. This preserves deterministic durable state while allowing network/inference latency to overlap. Concurrency follows execution topology rather than provider brand: cloud profiles may run up to four independent document windows concurrently, while local and LAN profiles remain serial unless a future explicit server-capacity capability says otherwise.

OpenRouter routing treats compatibility, privacy, and model precision as hard eligibility constraints. Document requests require parameter-compatible endpoints, deny provider data collection by default, honor the profile's optional ZDR requirement, and restrict eligible endpoint quantization to INT8, FP8/MXFP8, FP16, BF16, or FP32 execution. Independent document windows deliberately do not share a sticky `session_id`: they contain different source text, and real-provider acceptance showed negligible prompt-cache reuse while one sticky route could concentrate all concurrent work on the same slow endpoint. OpenRouter therefore retains its normal price/uptime load balancing across eligible routes, with a p90 throughput preference of at least 50 tokens/sec and a p90 latency preference of at most 20 seconds.

Provider resilience is based on transport inactivity rather than a blunt whole-request wall clock. The profile timeout bounds silence while connecting and between received SSE events. Any provider heartbeat/comment, reasoning delta, output delta, tool-argument delta, or final usage event proves the connection is responsive and resets that timer; an active request may therefore run as long as needed. A silent transport failure is retried once with the same logical request. Output exhaustion (`finish_reason=length`) is a separate condition: only truncation/output-shape pressure receives a smaller card budget. Completed windows remain checkpointed for Retry.

These rules apply to both initial generation and future document-aware tasks. New document features should reuse semantic chunks, capacity-bounded windows, deterministic native assembly, and the shared provider routing/concurrency policy rather than introducing feature-specific page loops or unbounded request fan-out.
