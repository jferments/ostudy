# Learning-experience stages: LK-08 through LK-14

Part of the [development plan](README.md). All implementation checkboxes start unchecked. The source/evidence and lifecycle contracts from [foundation stages](01-foundations.md) remain binding throughout.

## LK-08 — Rich study guides, viewer semantics and professional PDF

Outcome: source-grounded guides explain concepts, mechanisms, comparisons, worked examples and misconceptions with useful typography in the app and in a local navigable PDF.

Owners: existing guide generation/contracts, `src/ipc/studyGuides.ts`, `StudyGuideDialog.tsx`, `src/editor/`, native `document_study_guide*` and export owners. Introduce a narrow semantic block layer rather than a second rich-editor language.

- [ ] **08.1 Normalize current guide content.** Convert existing sections and overlays into explicit headings, paragraphs, terms, key-concept callouts, comparisons, tables, processes, figures, math, worked examples and retrieval checks as supported. One effective snapshot combines the immutable generated revision with compatible learner edits. Conflict preservation stays intact. Old field adapters belong at conversion, not in every renderer.
- [ ] **08.2 Improve authoring from shared context.** Generate objectives/prerequisites, coherent explanations, important definitions, qualified distinctions, examples, assumptions, exceptions and self-checks according to source needs. Do not require empty template sections everywhere. Preserve component/source support and existing admissible siblings. Bold important terms through semantic marks, not a global search-and-bold pass over final text.
- [ ] **08.3 Share screen/PDF meaning.** Both renderers consume the same effective block hierarchy, notes setting and source links. Use actual bold/italic faces, restrained headings/rules, light-grey Key Concepts panels, readable tables and captioned figures. A PDF theme is independent of the app's active dark theme. Export is selectable text where possible, not page screenshots.
- [ ] **08.4 Qualify the native PDF boundary.** Test the pinned backend first for linked contents, PDF bookmarks, heading tags/reading order, fonts/glyphs, table pagination, images and typeset math. These are separate requirements. Extend or replace only a demonstrated unsupported renderer boundary behind the existing native prepared-export API. No cloud converter or runtime Python/office dependency. Source notation is not a passing typeset-math result.
- [ ] **08.5 Add render and content regressions.** Cover multi-page tables, long terms, nested headings, orphan prevention, wide formulas, non-Latin text/fallback policy, notes on/off, contrast and visual structure. Test contents destinations and bookmark targets structurally; inspect reading order and actual rendered pages separately. Proposed `StudyGuideSemanticBlocks.test.tsx` and native guide-export fixtures are delivered here.

Exit: single-document and collection guides retain edits/support and exhibit the same semantic emphasis in viewer/PDF. Export makes zero provider requests, works offline, and uses qualified math/glyph behavior. No claim of PDF accessibility conformance is based only on the presence of a tag.

## LK-09 — Tutor projects and conversation management

Outcome: organize chats into projects/folders and operate Rename, Move, Archive and Delete through the row's overflow menu.

Owners: current Tutor repository/services, `src/ipc/tutor.ts`, Tutor history UI/controller, collection scope resolver, shared menus/confirmation/Back infrastructure. Project and document folder are distinct objects; a project references source folders.

- [ ] **09.1 Add project and organization state.** Store title, description/instructions, archive state, default SourceSelection and organization revision; give a conversation optional project membership and its own archive/title revision. Add focused native create/rename/move/archive/delete commands with expected revisions and retry identities. Validate bounded titles and selections.
- [ ] **09.2 Define inheritance once.** New conversations inherit current defaults. Moving an existing chat preserves its sources unless the human explicitly applies destination defaults. Project default edits affect future choices, never past turn snapshots. Common project membership does not opt chats into cross-conversation retrieval.
- [ ] **09.3 Deliver accessible menus.** Overflow appears on hover and keyboard focus and remains discoverable on touch. Use existing menu/confirmation primitives, filtered archive views and stable focus after row changes. Project deletion defaults to moving chats to ungrouped; chat deletion does not delete separately created materials.
- [ ] **09.4 Test concurrency/privacy.** Rename while receiving a response, move while a turn runs, delete/archive during refresh, stale revision, duplicate retry, source-default change, and excluded-source retrieval. A committed write followed by refresh failure remains successful. Update backup/deletion and any explicit sync contract without silently sharing private chats.

Exit: full organization works on compact/wide layouts and keyboard/Back paths. Historical sources and in-flight scope snapshots remain unchanged. No model deck-writing tool is enabled.

## LK-10 — Text-first responsive lessons and lesson plans

Outcome: generate a coordinated lesson from shared knowledge, view it on mobile/desktop, read its transcript, ask Tutor questions and answer pop quizzes without configuring speech.

Owners: proposed native `lessons/`, typed `src/ipc/lessons.ts`, lesson library/player controllers, current knowledge/context and question/Practice services, semantic content rendering from LK-08, existing navigation/task boundaries.

- [ ] **10.1 Persist the semantic composition.** Add lesson identity, immutable revision, source-set/coverage plan, ordered scenes, beats, script segments, visual blocks, support links and question references. IDs are stable through layout/reordering. A normal lesson targets roughly 10-30 teaching scenes; larger scopes become a lesson series, not a crushed textbook or a quota padded with filler. Store ordered lesson-plan entries and optional acyclic prerequisite links separately from completion.
- [ ] **10.2 Author coordinated content.** Plan objectives/depth/prerequisites; author a beat's visuals, script and question opportunity together from LearningContext. Validate support and consistency across channels, preserve qualifications, and repair failed candidates only. A diagram uses admitted figures or constrained typed data, never model-authored executable HTML/CSS/SVG. Scientific geometry is not aesthetic decoration. Native validation precedes publication.
- [ ] **10.3 Build one responsive player.** Implement concept, comparison, process, worked-example, figure and retrieval-check templates. Use container width, text scale and safe areas rather than OS sniffing. Stack independent blocks or step through existing beats; preserve all required content and accessible reading order. Keep spatial figures atomic with zoom/detail/text alternatives. Never shrink an entire fixed slide to unreadability or regenerate a mobile manuscript.
- [ ] **10.4 Integrate checks and Tutor.** Reuse current question compilers/evaluators and shared Practice bodies. Lesson checks have separate attempt/progress context and do not silently write FSRS reviews. Explicit Practice launches resolve existing card IDs and ordinary review rules. Pre-answer projections omit solutions, answer-bearing transcript/captions/media and reveal cues. Tutor receives the current scene/beat and permitted snapshot, not unrestricted lesson answers; replies do not rewrite the saved script.
- [ ] **10.5 Preserve progress.** Save acknowledged lesson revision, scene, beat, question-response state and later audio segment/offset. Resize, rotation and Tutor-pane changes preserve location and responses. New lesson revisions do not silently remap an old response to a new question key. Resume offers a controlled transition when compatibility is lost. Completion is not a mastery score.
- [ ] **10.6 Expose generation and navigation.** Add a bounded Lessons library/player destination integrated with existing navigation and Back restoration; no unrelated navigation redesign. Enable a third Lesson status link in automatic bundles only after text-only behavior qualifies. New uploads follow the selected material policy; do not enqueue every historical document. Transcript is available immediately and offline.

Exit: all lesson blocks remain readable at narrow/medium/wide containers and enlarged text, including with Tutor open. Resize and text-only navigation make zero provider calls. Questions, supports, progress and lesson plans survive restart/backup without introducing another grader or scheduler. Qualify real Linux/Android behavior before claiming mobile acceptance.

## LK-11 — Retained narration and speech settings

Outcome: synthesize validated narration once, retain it, replay offline, change voice without rewriting the lesson, and regenerate only missing compatible segments.

Owners: existing native AI profile/gateway/credential/task owners, proposed `ai/speech/`, `src/ipc/speech.ts`, AI/LLM settings, `lessons/` rendition repository, managed media, native/platform playback and backup. River/Kokoro are the requested default, not permission to substitute another available voice.

- [ ] **11.1 Qualify the provider contract.** Recheck the selected OpenRouter speech endpoint/catalog, model/voice identifiers, encoding, limits, controls and pricing units against official documentation and a deliberate bounded live request. Keep binary speech separate from text/structured-output decoding. Reject unsupported controls and retain actual producer metadata, including unknown revision where unavailable. Do not claim upstream idempotency or exactly-once billing without a documented capability.
- [ ] **11.2 Add settings and explicit preview.** Add Lesson narration role, provider/model/voice selection and capability status; cache catalog metadata for offline display. Use `hexgrad/kokoro-82m` and `af_river` only when admitted by the route. Settings opening never synthesizes a sample. Explicit sample playback and generation respect the selected credential/privacy/budget boundary; no hidden local runtime or system-speech substitute is required.
- [ ] **11.3 Normalize script and segmentation.** Store readable and spoken forms with explicit pronunciation bindings and cue IDs. Preserve numerical values, symbols, units and qualifications. Use coherent sentence/beat groups, not one request per word or an entire lecture. Only supported pronunciation controls are lowered; no assumed SSML support. Duration-based segment cues suffice; no STT model is added for alignment.
- [ ] **11.4 Retain bytes and receipts.** Key compatible audio by spoken text, model/voice/known producer version, language, applied pronunciation, synthesis options, normalizer/segmenter and encoding. Keep returned byte hash separate. Join concurrent matching jobs; bound requests/bytes/duration. Stream to staging, validate/decode/hash, move into managed storage, then commit reference/receipt with recovery for every interruption point. Successful segments survive a failed sibling or cancellation.
- [ ] **11.5 Make voice changes cost-safe.** Saving settings changes the desired rendition only. Retain old clips labeled previous voice. Generate the missing replacement once on the next authorized Listen or an explicit bounded batch update; never bill for the whole library on settings Save. In-flight jobs retain captured profiles and cannot activate as the new voice. Activate a complete coherent rendition; no silent mixed-voice lesson. Switching back reuses compatible retained clips.
- [ ] **11.6 Complete playback/lifecycle.** Read/Listen, play/pause, scene/beat seek, transcript visibility, local speed, volume and acknowledged position. Prompt/solution clips have separate reveal permission and preload manifests. Android audio focus/background/interruption/Bluetooth/Back behavior uses qualified platform ports. Opening Tutor has an explicit pause/resume rule. Layout changes never restart or regenerate speech.
- [ ] **11.7 Protect paid media.** Active and explicitly retained previous narration is not LRU cache. Include it in full backup/integrity manifests and explicit lesson transfer choices. Space pressure stops new optional speech and preserves transcript/audio already owned. Deliberate removal warns about regeneration cost. Ambiguously accepted remote requests are recorded and not blindly retried; local deduplication cannot prove no duplicate remote charge.

Exit: repeated/reboot/offline playback, switching back, export and local speed changes make zero TTS calls. Script/pronunciation edits invalidate only dependent segments. Profile-change races, full disk, corrupt/truncated audio, cancellation and lost-response tests pass. Live River pronunciation and physical Android listening remain separate observed gates, not inferred from mocks.

## LK-12 — Local PowerPoint export

Outcome: compile the same lesson into editable modern `.pptx` slides with transcript speaker notes and optional already-saved narration. The in-app player remains responsive and does not render PowerPoint screenshots.

Owners: native lesson effective snapshots, external-file prepared exports, proposed local `src/platform/presentationExport/` adapter, managed media and deterministic layout. No Node/Python/office installation becomes an end-user prerequisite.

- [ ] **12.1 Select a bounded serialization adapter.** Qualify the design's browser-capable PptxGenJS candidate against actual WebViews, worker/binary handling, fonts, notes, shapes, figures and embedded audio. Pin/license-audit only the chosen dependency. If the candidate cannot meet a required capability, select a native/local alternative behind the same contract; do not add a cloud exporter or source-writing Action.
- [ ] **12.2 Compile layout without an LLM.** Default to fixed 16:9 slides. Map scene/beat IDs to slides/continuations with readable text, native editable shapes/tables where practical, admitted images and qualified math/vector fallbacks. Keep source/accessible text. Do not rasterize whole slides or rewrite content for different screen sizes. Stable overflow rules generate continuation slides rather than tiny text.
- [ ] **12.3 Preserve narration and disclosure.** Assign each slide only its script portions in notes. Include matching current saved audio by default with an explicit omit option. Missing audio permits audio-free export or separate deliberate generation, never a hidden TTS call. Join/re-encode segment audio locally when necessary using a qualified codec path; arbitrary MP3 byte concatenation is not sufficient. Learner copy excludes answer notes/clips; an explicit instructor/answer-section choice may disclose them.
- [ ] **12.4 Use native export lifecycle.** Rust authorizes a frozen bounded lesson/media snapshot. Serialize locally without secrets or provider access, pass output through a bounded binary/staging mechanism, and validate container/relationships/size before registering the prepared export. Keep operation identity and crash cleanup. No macros, arbitrary scripts, remote resources or live-chat imitation.
- [ ] **12.5 Test actual interoperability.** Validate OOXML structure, media relationships, notes mapping, editability expectations, no clipping, sources and audio. Open fixtures in Microsoft PowerPoint and LibreOffice Impress where available, recording application/version/OS. Missing applications remain unrun human gates. A valid ZIP/XML file alone does not certify visual/audio compatibility.

Exit: offline export/re-export uses the same saved lesson and zero provider calls. Continuation slides neither repeat full narration nor duplicate question identities. Sharing choices cannot expose private Tutor text, learner notes or answer audio accidentally.

## LK-13 — Final baseline consolidation and integrated data adoption

Outcome: current runtime uses one current representation; the old migration chain and obsolete readers are archived after the actual retained library is safely converted and verified.

Owners: LK-02's transition boundary, final schema/current payloads, startup/restore, backup/assets, validators and documentation. Exact procedure and evidence are in [data transition](03-data-and-validation.md).

- [ ] **13.1 Freeze final data contracts.** After LK-12's schema changes, identify the exact candidate schema and supported current interchange/sync payloads. Build a curated current-schema baseline with a new explicit lineage/baseline identity where needed. Prove its tables/indexes/triggers/constraints/FTS configuration match the latest migrated schema. Do not just concatenate old SQL or change the version number.
- [ ] **13.2 Convert isolated copies first.** Use the known old chain plus narrowly scoped transformations to reach the final current representation; preserve primary identities, values, history, assets and annotations. Test current-to-current no-op, interrupted conversion, corrupt/unknown schema refusal and old backup recovery. No reset, uninstall, force adoption, or lossy export/import as a substitute for conversion.
- [ ] **13.3 Obtain actual-library evidence.** Provide the maintained local backup/inspection/conversion/verification workflow. Keep source content on the user's machine. Record exact converter SHA, input lineage/version, backup and asset manifest integrity, preserved counts/digests, current output identity and successful reopen/restore. This human-run boundary is required because repository/CI access is not access to the personal library.
- [ ] **13.4 Retire old runtime machinery.** After that gate, archive previous migration SQL/converters/fixtures with provenance outside normal compile/startup/package/test paths; remove obsolete consumers and version branches in a coordinated change. Keep an explicit offline historical-backup conversion route, not silent support in every runtime reader. Update checksum/baseline guards and tests to assert the new contract without weakening preservation tests.
- [ ] **13.5 Repeat integrated recovery.** Full-library restore covers all sources, references, questions, schedules/reviews, edits, collection summaries, conversations, lessons and retained audio. Content-only transfer retains fresh schedules and excludes donor private history. Sync either negotiates its supported lesson graph explicitly or rejects it before partial transfer; never silently advertises unsupported coverage.

Exit: one qualified baseline/current runtime; archived history remains recoverable; actual-library adoption is recorded separately from synthetic evidence. Old code is not removed while the only available recovery path still depends on it. Subsequent real schema changes use small forward migrations and normalize before runtime; public-release compatibility policy is decided at release, not guessed now.

## LK-14 — Whole-product qualification and handoff

Outcome: the complete Week 1 workflow is exercised against an immutable published candidate, with automated and human evidence separated.

- [ ] **14.1 Finish source/documentation audit before freeze.** Reconcile the stage checklists, native commands, active data formats, user guides, help, provider defaults, feature flags and known limitations. Remove demonstrably obsolete implementation/styling only with ownership evidence. Resolve all blocking findings before expensive terminal qualification starts.
- [ ] **14.2 Qualify exact source.** Run maintained static/fast, full Linux, Android compile/package and emulator gates on the frozen head. Record explicit reuse only under current repository policy; old green ancestors are not new results. Read named steps, not only workflow color. No CI-state toggles, skipped assertions, no-op commits, arbitrary sleeps or widened permissions to obtain green.
- [ ] **14.3 Exercise the combined scenario.** Import readings, sparse slides, notes/assignment and overlapping screenshots; generate one combined bundle; use folder-scoped Tutor; read guide/PDF; study responsive lesson/checks; synthesize River once; replay offline; change voice and reuse the old one; export notes/audio PPTX; back up/restore; add the prepared source to Week 2. Verify request counters and preserved data.
- [ ] **14.4 Record remaining human evidence.** Real extraction/teaching quality, PDF reading order/appearance, speech pronunciation, physical-device lifecycle and office-application compatibility each name the actual observed platform and source SHA. Missing evidence remains explicitly pending. Do not call a source-reviewed fixture corpus an independent external audit.
- [ ] **14.5 Hand off without merging.** Report branch/head/base/last parent, completed boundaries, actual tests and SHAs, failed/unrun gates, local safe checkout/build/debug instructions, remaining acceptance and writer release. No automatic merge or background promise. Nonblocking late findings become follow-up work rather than invalidating a qualified candidate through unrelated cleanup.

Exit: acceptance reconciled, exact-source automated evidence recorded, manual gates observed or explicitly assigned, and the human has the review/merge decision.
